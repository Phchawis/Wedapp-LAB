# ระเบียบปฏิบัติ: การควบคุมเอกสารและบันทึกด้วยระบบสารสนเทศ

**ระบบทะเบียนเอกสารคุณภาพห้องปฏิบัติการเทคนิคการแพทย์ (Lab QMS)**

> **ร่างเพื่อพิจารณา** — เขียนจากพฤติกรรมจริงของระบบที่ตรวจสอบกับโค้ดและฐานข้อมูล
> เมื่อ 14 กันยายน 2569 ทุกค่าตัวเลขในเอกสารนี้เป็นค่าที่ระบบใช้จริง ไม่ใช่ค่าที่ควรจะเป็น
> กรุณาตรวจทาน กำหนดเลขที่เอกสาร ผู้ทบทวน ผู้อนุมัติ แล้วเข้ากระบวนการควบคุมเอกสาร

## 1. วัตถุประสงค์

กำหนดวิธีควบคุมเอกสารและบันทึกคุณภาพของห้องปฏิบัติการเทคนิคการแพทย์ผ่านระบบสารสนเทศ
ให้เป็นไปตาม ISO 15189:2022 โดยมั่นใจได้ว่า

1. ผู้ปฏิบัติงานใช้เอกสารฉบับที่ถูกต้องและเป็นปัจจุบันเสมอ
2. มีหลักฐานว่าใครจัดทำ ทบทวน อนุมัติ และรับทราบเอกสารใดเมื่อใด
3. ข้อมูลไม่สูญหาย ไม่ถูกแก้ไขโดยไม่ทิ้งร่องรอย และเข้าถึงได้เฉพาะผู้มีสิทธิ์
4. ห้องปฏิบัติการยังทำงานต่อได้เมื่อระบบใช้งานไม่ได้

## 2. ขอบเขต

### 2.1 หมวดงานที่ครอบคลุม

งานห้องปฏิบัติการเทคนิคการแพทย์ · รับสิ่งส่งตรวจและห้องปฏิบัติการส่งต่อ · โลหิตวิทยา ·
จุลทรรศนศาสตร์และปรสิตวิทยา · เคมีคลินิก · ภูมิคุ้มกันวิทยา · บริหารสิ่งส่งตรวจและบริการผู้ป่วยนอก ·
บริหารจัดการสิ่งส่งตรวจและบริการศูนย์การแพทย์ · บริหารจัดการเครื่องมือ ณ จุดดูแลผู้ป่วย ·
ศูนย์ปฏิบัติการตรวจวินิจฉัยทางการแพทย์ · ธุรการและคลังพัสดุห้องปฏิบัติการ · เวชสารสนเทศห้องปฏิบัติการ

### 2.2 สิ่งที่ไม่ครอบคลุม

| ไม่ครอบคลุม | ควบคุมด้วย |
|---|---|
| ผลการตรวจวิเคราะห์ผู้ป่วย | ระบบสารสนเทศห้องปฏิบัติการ (LIS) |
| ข้อมูลบุคลากรรายบุคคล | ระบบทะเบียนบุคลากร |
| เอกสารที่ยังใช้กระดาษล้วนโดยไม่ลงทะเบียนในระบบ | ระเบียบควบคุมเอกสารฉบับกระดาษ |
| ข้อมูลควบคุมคุณภาพรายวัน | ระบบควบคุมคุณภาพห้องปฏิบัติการ |

## 3. คำจำกัดความ

| คำ | ความหมายในระเบียบนี้ |
|---|---|
| เอกสารควบคุม | เอกสารที่ระบบทำเครื่องหมายว่าควบคุม ต้องใช้ฉบับล่าสุดจากระบบเท่านั้น |
| สำเนาไม่ควบคุม | เอกสารที่พิมพ์ออกจากระบบ ไม่รับประกันว่าเป็นฉบับปัจจุบัน |
| แก้ไขครั้งที่ (rev) | เลขลำดับการแก้ไข ระบบเพิ่มให้เองเมื่อเปลี่ยนสถานะหรืออัปเดตไฟล์แนบ |
| การรับทราบ | การลงลายมือชื่ออิเล็กทรอนิกส์ยืนยันว่าได้อ่านเอกสารฉบับนั้นแล้ว |
| บันทึกกิจกรรม | ร่องรอยที่ระบบเก็บอัตโนมัติว่าผู้ใช้คนใดทำอะไรกับเอกสารใดเมื่อใด |
| ชุดกู้ชีพออฟไลน์ | ไฟล์บีบอัดรวมทะเบียนและไฟล์เอกสาร ใช้ยามระบบใช้งานไม่ได้ |
| RPO | ปริมาณข้อมูลที่ยอมให้สูญหายสูงสุดเมื่อเกิดเหตุ วัดเป็นเวลา |
| RTO | ระยะเวลาที่ยอมให้ระบบใช้งานไม่ได้ก่อนต้องกลับมาทำงาน |

## 4. หน้าที่ความรับผิดชอบ

สิทธิ์ในระบบแบ่งเป็น 7 ระดับ **ระบบบังคับสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่มบนหน้าจอ**
ผู้ใช้ที่ไม่มีสิทธิ์จะถูกปฏิเสธแม้เรียกใช้ผ่านช่องทางอื่น รายละเอียดดูภาคผนวก ก

| ระดับ | หน้าที่ |
|---|---|
| ผู้ดูแลระบบ | ดูแลระบบและบัญชีผู้ใช้งาน · สำรองและกู้คืนข้อมูล · ทบทวนสิทธิ์ |
| หัวหน้างาน | อนุมัติและประกาศใช้เอกสาร · ตรวจบันทึกกิจกรรม · รับทราบผลตัวชี้วัด |
| หัวหน้าหมวดงาน | ลงทะเบียน แก้ไข ประกาศใช้เอกสารในหมวดงานของตน · ติดตามการรับทราบ · ตรวจเอกสารถึงกำหนดทบทวน |
| ผู้จัดการเอกสาร | ลงทะเบียนและแนบไฟล์เอกสาร · ดูแลความครบถ้วนของทะเบียน |
| นักเทคนิคการแพทย์ | อ่าน รับทราบ เสนอแก้ไขเอกสาร |
| ผู้ช่วยนักเทคนิคการแพทย์ | อ่านและรับทราบเอกสาร |
| เจ้าหน้าที่ธุรการ | อ่านและรับทราบเอกสาร |

**ต้องระบุชื่อผู้รับผิดชอบจริงในแต่ละบทบาทก่อนอนุมัติระเบียบนี้**

## 6. การเข้าใช้งานระบบและการจัดการบัญชี

### 6.1 การยืนยันตัวตน

ระบบใช้ชื่อผู้ใช้งานคู่กับรหัสผ่าน รหัสผ่านเก็บเป็นค่าที่ผ่านการเข้ารหัสทางเดียว
**ไม่มีผู้ใดรวมทั้งผู้ดูแลระบบอ่านรหัสผ่านของผู้ใช้ได้** การเชื่อมต่อเข้ารหัสตลอดเส้นทาง

ชื่อผู้ใช้งานใช้**รหัสบุคลากร** เพื่อให้ตรงกับทะเบียนบุคลากรและตรวจสอบย้อนกลับได้

### 6.2 นโยบายรหัสผ่าน

| ข้อกำหนด | ค่าที่ระบบบังคับ |
|---|---|
| ความยาวขั้นต่ำเมื่อผู้ใช้ตั้งเอง | 8 ตัวอักษร |
| ความยาวขั้นต่ำเมื่อผู้ดูแลตั้งให้ | 6 ตัวอักษร (เป็นรหัสชั่วคราว) |
| ห้ามซ้ำรหัสเดิม | ระบบปฏิเสธถ้าตั้งใหม่ซ้ำกับรหัสเดิม |
| การเปิดเผยรหัสชั่วคราว | แจ้งผู้ใช้โดยตรง ห้ามส่งผ่านช่องทางสาธารณะ |

ผู้ใช้ต้องไม่ใช้รหัสผ่านร่วมกัน การกระทำใดที่เกิดจากบัญชีใด ถือเป็นการกระทำของเจ้าของบัญชีนั้น

### 6.3 การสร้างบัญชีใหม่

ผู้มีสิทธิ์จัดการผู้ใช้งานสร้างบัญชีพร้อมรหัสผ่านชั่วคราว **ระบบบังคับให้ผู้ใช้ตั้งรหัสผ่านใหม่
ก่อนใช้งานครั้งแรก** ผู้ใช้ที่ยังไม่ตั้งรหัสใหม่จะถูกปฏิเสธการใช้งานทุกคำสั่ง

ต้องบันทึกอีเมลของผู้ใช้ทุกคนตั้งแต่สร้างบัญชี เพื่อให้ตั้งรหัสผ่านใหม่เองได้เมื่อลืม

### 6.4 การลืมรหัสผ่าน

| ขั้นตอน | รายละเอียด |
|---|---|
| วิธีขอ | ผู้ใช้กรอกอีเมลที่บันทึกไว้ในระบบ |
| อายุลิงก์ | 30 นาที |
| จำนวนครั้งสูงสุด | 5 ครั้งต่อชั่วโมงต่อบัญชี |
| การเก็บลิงก์ | ระบบเก็บเฉพาะค่าที่ผ่านการเข้ารหัส ไม่เก็บลิงก์จริง |
| การตอบกลับ | ระบบตอบข้อความเดียวกันเสมอ ไม่บอกว่าอีเมลนั้นมีบัญชีหรือไม่ |

**ผู้ใช้ที่ยังไม่มีอีเมลในระบบต้องติดต่อผู้ดูแลระบบ** ผู้รับผิดชอบต้องติดตามให้ครบทุกคน

### 6.5 การเข้าสู่ระบบผ่านระบบทะเบียนเอกสารกลาง

ระบบรองรับการเข้าสู่ระบบต่อเนื่องจากระบบทะเบียนเอกสารกลาง (Masterlist)
โดยใช้กุญแจร่วมที่ทั้งสองระบบมีตรงกัน **ผู้ใช้ต้องมีบัญชีในระบบนี้อยู่ก่อน**
ระบบไม่สร้างบัญชีใหม่ให้อัตโนมัติ

กุญแจร่วมต้องเปลี่ยนเมื่อสงสัยว่ารั่ว หรือเมื่อผู้ที่เคยเข้าถึงพ้นหน้าที่

### 6.6 อายุเซสชัน

เซสชันมีอายุ **12 ชั่วโมง** เมื่อหมดอายุต้องเข้าสู่ระบบใหม่
บัญชีที่ถูกลบหรือระงับจะใช้เซสชันเดิมต่อไม่ได้ทันที

ผู้ใช้ต้องออกจากระบบทุกครั้งเมื่อใช้เครื่องคอมพิวเตอร์ร่วมกับผู้อื่น

### 6.7 การพ้นหน้าที่

เมื่อผู้ใช้ลาออก ย้าย หรือพ้นหน้าที่ **ผู้ดูแลระบบต้องระงับหรือลบบัญชีภายใน 1 วันทำการ**
บันทึกกิจกรรมและลายมือชื่อรับทราบที่เกิดขึ้นแล้วยังคงอยู่เป็นหลักฐาน

### 6.8 การทบทวนสิทธิ์

ผู้ดูแลระบบร่วมกับหัวหน้างานทบทวนรายชื่อผู้ใช้และระดับสิทธิ์**ปีละครั้งเป็นอย่างน้อย**
ตรวจว่าไม่มีบัญชีของผู้ที่พ้นหน้าที่แล้ว และไม่มีผู้ใดได้สิทธิ์เกินความจำเป็น
บันทึกผลการทบทวนไว้เป็นหลักฐาน

## 7. การจำแนกและเลขที่เอกสาร

เลขที่เอกสารประกอบด้วย **ประเภท-หมวดงาน-ลำดับ** เช่น `SOP-HEM-014`
ระบบไม่ยอมให้ลงทะเบียนเลขที่ซ้ำ

**ห้ามเปลี่ยนเลขที่เอกสารที่ประกาศใช้แล้ว** หากจำเป็นต้องเปลี่ยน ให้ยกเลิกฉบับเดิม
แล้วลงทะเบียนใหม่ พร้อมระบุความเชื่อมโยงไว้ในชื่อหรือคำอธิบายเอกสาร

## 8. วงจรควบคุมเอกสาร

### 8.1 สถานะเอกสาร

| สถานะ | ความหมาย | ใช้ปฏิบัติงานได้ |
|---|---|:-:|
| ร่าง | อยู่ระหว่างจัดทำ | ✗ |
| รอทบทวน | ส่งให้ผู้ทบทวนพิจารณา | ✗ |
| อนุมัติแล้ว | ผ่านการอนุมัติ รอประกาศใช้ | ✗ |
| ประกาศใช้ | เป็นฉบับที่ผู้ปฏิบัติต้องใช้ | ✓ |
| สำเนาควบคุม | สำเนาที่ควบคุมการแจกจ่าย | ✓ |
| ยกเลิกใช้งาน | ไม่ใช้แล้ว เก็บไว้เป็นหลักฐาน | ✗ |

### 8.2 เส้นทางเปลี่ยนสถานะและสิทธิ์ที่ต้องใช้

ระบบอนุญาตเฉพาะเส้นทางในตารางนี้ เส้นทางอื่นถูกปฏิเสธที่เซิร์ฟเวอร์

| จากสถานะ | ไปสถานะ | ต้องมีสิทธิ์ |
|---|---|---|
| ร่าง | รอทบทวน | บันทึกแก้ไข |
| ร่าง | ประกาศใช้ | ประกาศใช้ |
| รอทบทวน | อนุมัติแล้ว | อนุมัติ |
| รอทบทวน | ประกาศใช้ | ประกาศใช้ |
| อนุมัติแล้ว | ประกาศใช้ | ประกาศใช้ |
| ประกาศใช้ | สำเนาควบคุม · ยกเลิกใช้งาน | ลงทะเบียน |
| สำเนาควบคุม | ประกาศใช้ · ยกเลิกใช้งาน | ประกาศใช้ · ลงทะเบียน |
| ทุกสถานะ | กลับไปรอทบทวน | บันทึกแก้ไข |

### 8.3 การบันทึกผู้ทบทวนและผู้อนุมัติ

**ระบบบันทึกชื่อจากผู้ที่กดจริง ไม่ให้พิมพ์ชื่อผู้อื่นแทน**

- เปลี่ยนสถานะเป็น *รอทบทวน* → ระบบบันทึกผู้กดเป็น **ผู้ทบทวน**
- เปลี่ยนสถานะเป็น *ประกาศใช้* → ระบบบันทึกผู้กดเป็น **ผู้อนุมัติ**

ข้อมูลควบคุมเอกสาร (ผู้ทบทวน ผู้อนุมัติ กำหนดทบทวนถัดไป สถานะควบคุม)
แก้ไขได้เฉพาะผู้มีสิทธิ์ประกาศใช้

> ผู้ทบทวนและผู้อนุมัติต้องเป็นคนละคนกัน หากจำเป็นต้องเป็นคนเดียวกัน
> ต้องบันทึกเหตุผลไว้และให้หัวหน้างานรับทราบ

### 8.4 การป้องกันการแก้เลขฉบับโดยพลการ

เลขแก้ไขครั้งที่และวันที่ปรับปรุงเป็นค่าที่ระบบปรับให้พร้อมการเปลี่ยนสถานะ
**ผู้ใช้แก้ไขค่าเหล่านี้โดยตรงไม่ได้** เพื่อกันการอ้างเลขฉบับที่ไม่ตรงความจริง

### 8.5 การเสนอแก้ไขเอกสาร

นักเทคนิคการแพทย์เสนอแก้ไขเอกสารได้ แต่ไม่มีสิทธิ์แก้ไขหรือประกาศใช้เอง
ข้อเสนอต้องผ่านหัวหน้าหมวดงานหรือหัวหน้างานพิจารณา

## 9. ไฟล์แนบ

### 9.1 ชนิดและขนาดไฟล์ที่ระบบรับ

| หัวข้อ | ค่าที่ระบบบังคับ |
|---|---|
| ขนาดสูงสุดต่อไฟล์ | 50 MB |
| เอกสาร | pdf · doc · docx · docm · dot · dotx · odt · rtf |
| ตาราง | xls · xlsx · xlsm · xlt · xltx · ods · csv |
| นำเสนอ | ppt · pptx · ppsx · odp |
| รูปภาพ | png · jpg · jpeg · gif · webp · bmp · tif · tiff · heic · heif |
| ข้อความ | txt |

> **ระบบไม่รับไฟล์ .html .htm .svg และ .zip โดยเจตนา** เพราะเป็นไฟล์ที่แฝงสคริปต์
> หรือไฟล์อื่นเข้ามาได้ ห้ามหาวิธีหลบข้อจำกัดนี้ด้วยการเปลี่ยนนามสกุลไฟล์

**แนะนำให้แนบ PDF เป็นฉบับใช้งาน** และแนบไฟล์ต้นฉบับที่แก้ไขได้ควบคู่เมื่อจำเป็น
เพื่อกันการแก้ไขเอกสารโดยไม่ผ่านกระบวนการควบคุม

### 9.2 การอัปเดตไฟล์เป็นฉบับใหม่

เมื่อผู้มีสิทธิ์กดอัปเดตไฟล์แนบ ระบบจะ

1. บันทึกไฟล์ใหม่เข้าระบบ
2. เพิ่มเลขแก้ไขครั้งที่ของเอกสารขึ้นหนึ่ง
3. ปรับวันที่ปรับปรุงเป็นวันปัจจุบัน
4. บันทึกกิจกรรมว่าใครอัปเดตเอกสารใดเมื่อใด

### 9.3 ข้อควรระวังสำคัญ — ไฟล์ฉบับเดิมถูกลบออกจากระบบ

> **ระบบลบไฟล์ฉบับเดิมออกจากเซิร์ฟเวอร์เมื่ออัปเดตเป็นฉบับใหม่**
> ในระบบจะเหลือเฉพาะไฟล์ฉบับล่าสุด เปิดดูไฟล์ฉบับก่อนหน้าจากระบบไม่ได้

| ประเด็น | มาตรการควบคุม |
|---|---|
| ต้องเก็บฉบับก่อนหน้าเป็นหลักฐาน | **ดาวน์โหลดไฟล์ฉบับเดิมเก็บไว้ก่อนกดอัปเดตทุกครั้ง** |
| หากลืมดาวน์โหลด | ไฟล์ฉบับเดิมอยู่ในระบบสำรองนอกสถานที่ โฟลเดอร์ `files-replaced` แยกตามวันที่ ติดต่อผู้ดูแลระบบเพื่อขอกู้คืน |
| ต้องการเก็บทั้งสองฉบับในระบบ | แนบเป็นไฟล์ใหม่แทนการกดอัปเดต แล้วระบุฉบับไว้ในชื่อไฟล์ |

ข้อนี้เป็นข้อจำกัดที่ทราบแล้วของระบบ ผู้รับผิดชอบต้องสื่อสารให้ผู้มีสิทธิ์อัปโหลดทุกคนทราบ
และทบทวนซ้ำในการอบรมประจำปี

### 9.4 ลิงก์ภายนอก

ระบบแนบลิงก์ไปยังเอกสารภายนอกได้ แต่**ลิงก์ไม่ใช่เอกสารควบคุม**
เนื้อหาปลายทางเปลี่ยนได้โดยระบบไม่รู้ หากเนื้อหานั้นจำเป็นต่อการปฏิบัติงาน
ต้องดาวน์โหลดมาแนบเป็นไฟล์ในระบบ ไม่ใช้ลิงก์อย่างเดียว
ลิงก์อัปเดตเป็นฉบับใหม่ผ่านคำสั่งอัปเดตไฟล์ไม่ได้

## 10. การรับทราบเอกสาร

### 10.1 วิธีปฏิบัติ

ผู้ปฏิบัติงานเปิดอ่านเอกสารแล้วกดรับทราบ **ระบบบังคับให้กรอกรหัสผ่านซ้ำเพื่อยืนยันตัวตน**
ถือเป็นลายมือชื่ออิเล็กทรอนิกส์ตามพระราชบัญญัติว่าด้วยธุรกรรมทางอิเล็กทรอนิกส์

### 10.2 การผูกกับฉบับเอกสาร

การรับทราบผูกกับ**ฉบับแก้ไขที่อ่าน** หนึ่งคนรับทราบหนึ่งฉบับได้ครั้งเดียว
เมื่อเอกสารแก้ไขเป็นฉบับใหม่ ผู้ปฏิบัติงานต้องรับทราบใหม่

ทำให้ตรวจสอบได้ว่าใครรับทราบฉบับใดแล้ว และใครยังไม่ได้รับทราบฉบับปัจจุบัน

### 10.3 การติดตาม

หัวหน้าหมวดงานต้องติดตามให้ผู้ปฏิบัติงานที่เกี่ยวข้องรับทราบเอกสารฉบับปัจจุบันครบทุกคน
**ภายใน 30 วันนับจากวันประกาศใช้** จึงถือว่าการสื่อสารเอกสารเสร็จสมบูรณ์

กรณีเอกสารที่มีผลต่อความปลอดภัยผู้ป่วยหรือผู้ปฏิบัติงาน ต้องรับทราบก่อนเริ่มปฏิบัติตาม

## 11. การพิมพ์เอกสารออกจากระบบ

> **เอกสารที่พิมพ์ออกจากระบบถือเป็นสำเนาไม่ควบคุม** เพราะไม่มีกลไกใดรับประกัน
> ว่ากระดาษในมือเป็นฉบับเดียวกับในระบบ ณ เวลาที่ใช้งาน

| สถานการณ์ | ข้อปฏิบัติ |
|---|---|
| ต้องการอ้างอิงขณะปฏิบัติงาน | เปิดจากระบบโดยตรง |
| จำเป็นต้องใช้กระดาษ ณ จุดปฏิบัติงาน | ต้องได้รับอนุมัติจากหัวหน้าหมวดงาน ประทับ "สำเนาควบคุม" ระบุเลขฉบับและวันที่พิมพ์ ขึ้นทะเบียนจุดแจกจ่าย และเก็บคืนทำลายเมื่อมีฉบับใหม่ |
| พิมพ์เพื่อประชุมหรือส่งผู้ตรวจประเมิน | ประทับหรือระบุ "สำเนาไม่ควบคุม" พร้อมวันที่พิมพ์ |

## 12. เอกสารจากภายนอก

เอกสารจากภายนอก เช่น มาตรฐาน แนวทางวิชาการ คู่มือเครื่องมือ เอกสารกำกับน้ำยา
ให้ลงทะเบียนเป็นประเภท **RF (เอกสารอ้างอิง)** หรือ **SD (เอกสารสนับสนุน)**

ต้องระบุแหล่งที่มาและฉบับปีของเอกสารต้นทางไว้ในชื่อเอกสาร
และตรวจสอบว่ามีฉบับใหม่กว่าหรือไม่**อย่างน้อยปีละครั้ง**
เอกสารจากภายนอกที่ล้าสมัยให้เปลี่ยนสถานะเป็นยกเลิกใช้งานเช่นเดียวกับเอกสารภายใน

## 13. แบบฟอร์มและบันทึกที่เกิดจากแบบฟอร์ม

| สิ่งที่ควบคุม | วิธีควบคุม |
|---|---|
| ตัวแบบฟอร์มเปล่า (FM · WS · EF) | เป็นเอกสารควบคุม ผ่านวงจรตามข้อ 8 |
| แบบฟอร์มที่กรอกแล้ว | เป็นบันทึก ควบคุมตามข้อ 16 |

**แบบฟอร์มที่กรอกแล้วต้องไม่เก็บทับตัวแบบฟอร์มเปล่าในทะเบียนเดียวกัน**
ให้ลงทะเบียนแยก หรือเก็บตามระเบียบการจัดเก็บบันทึกของหมวดงาน

เมื่อแบบฟอร์มเปลี่ยนฉบับ ต้องเก็บแบบฟอร์มเปล่าฉบับเดิมออกจากจุดใช้งานทันที
และบันทึกที่กรอกด้วยแบบฟอร์มฉบับเดิมยังคงมีผลเป็นหลักฐานตามเดิม

## 14. การทบทวนเอกสารตามรอบ

ผู้อนุมัติกำหนดวันทบทวนถัดไปของเอกสารแต่ละฉบับ ระบบแสดงวันดังกล่าวในหน้ารายละเอียดเอกสาร

> **ระบบยังไม่มีการแจ้งเตือนอัตโนมัติเมื่อถึงกำหนดทบทวน**
> ผู้รับผิดชอบต้องตรวจทะเบียนด้วยตนเอง**อย่างน้อยทุก 3 เดือน** เพื่อหาเอกสาร
> ที่ถึงกำหนดหรือเลยกำหนด แล้วบันทึกผลการตรวจไว้เป็นหลักฐาน

รอบการทบทวนที่แนะนำ

| ประเภทเอกสาร | รอบทบทวน |
|---|---|
| คู่มือคุณภาพ | 1 ปี |
| ระเบียบปฏิบัติ · วิธีปฏิบัติ | 2 ปี หรือเมื่อมีการเปลี่ยนแปลงวิธีทำงาน |
| แบบฟอร์ม | เมื่อมีการเปลี่ยนแปลง |
| เอกสารจากภายนอก | 1 ปี |

ต้องทบทวนทันทีโดยไม่รอรอบ เมื่อเปลี่ยนเครื่องมือ เปลี่ยนน้ำยา เปลี่ยนวิธีตรวจ
พบข้อบกพร่องจากการปฏิบัติตามเอกสาร หรือมีข้อกำหนดภายนอกเปลี่ยนแปลง

## 15. การยกเลิกเอกสารและการป้องกันการใช้ฉบับล้าสมัย

เมื่อเอกสารเปลี่ยนสถานะเป็น *ยกเลิกใช้งาน* ระบบยังเก็บเอกสารไว้เป็นหลักฐาน
แต่แสดงสถานะชัดเจนว่ายกเลิกแล้ว

ผู้รับผิดชอบต้องเก็บเอกสารฉบับกระดาษที่ยกเลิกออกจากจุดปฏิบัติงาน**ภายในวันเดียวกัน**
หรือประทับตราว่ายกเลิก เพื่อกันการหยิบไปใช้โดยไม่ตั้งใจ

## 16. การควบคุมบันทึกและระยะเวลาจัดเก็บ

| เรื่อง | ข้อกำหนด |
|---|---|
| ระยะเวลาจัดเก็บ | กำหนดรายฉบับเป็น 2 ปี 5 ปี หรือ 10 ปี |
| ค่าเริ่มต้น | 5 ปี |
| การเข้าถึง | ตามสิทธิ์ในภาคผนวก ก |
| การแก้ไข | ระบบบันทึกทุกการกระทำ แก้ไขโดยไม่ทิ้งร่องรอยไม่ได้ |
| การทำลาย | เมื่อครบระยะจัดเก็บ ต้องได้รับอนุมัติจากหัวหน้างานก่อน และบันทึกการทำลายไว้ |

ระยะจัดเก็บต้องไม่สั้นกว่าที่กฎหมายหรือข้อกำหนดของโรงพยาบาลกำหนด
หากมีข้อขัดแย้ง ให้ยึดระยะที่ยาวกว่า

## 17. ความลับและการคุ้มครองข้อมูลส่วนบุคคล

ผู้ใช้ทุกคนต้องรักษาความลับของข้อมูลที่เข้าถึงได้ผ่านระบบ และใช้เพื่อการปฏิบัติงานเท่านั้น

> **ระบบกำหนดสิทธิ์ตามบทบาท ไม่ใช่รายเอกสาร** ผู้ที่มีสิทธิ์อ่านจะเห็นเอกสารทุกฉบับในระบบ

ดังนั้น **ห้ามนำข้อมูลต่อไปนี้เข้าระบบ**

- ข้อมูลผู้ป่วยที่ระบุตัวบุคคลได้
- บันทึกการเฝ้าระวังสุขภาพรายบุคคลของผู้ปฏิบัติงาน
- ข้อมูลส่วนบุคคลอ่อนไหวตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล มาตรา 26
- เอกสารที่ต้องจำกัดการเข้าถึงเฉพาะบุคคลบางคน

หากจำเป็นต้องใช้ตัวอย่างผลตรวจประกอบเอกสาร ให้ปกปิดข้อมูลที่ระบุตัวบุคคลก่อน

## 18. ความปลอดภัยของข้อมูลและการตรวจสอบย้อนกลับ

### 18.1 มาตรการที่ระบบมี

| มาตรการ | รายละเอียด |
|---|---|
| การเข้ารหัสการเชื่อมต่อ | ทุกการเชื่อมต่อเข้ารหัส |
| รหัสผ่าน | เก็บเป็นค่าเข้ารหัสทางเดียว อ่านย้อนกลับไม่ได้ |
| สิทธิ์ตามบทบาท | บังคับที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม |
| อายุเซสชัน | 12 ชั่วโมง |
| บัญชีที่ถูกลบ | ใช้เซสชันเดิมต่อไม่ได้ |
| ชนิดไฟล์ | ปฏิเสธไฟล์ที่รันสคริปต์ได้ |
| บันทึกกิจกรรม | เก็บผู้ใช้ บทบาท การกระทำ เป้าหมาย และเวลา |

### 18.2 บันทึกกิจกรรมที่ระบบเก็บ

ครอบคลุมการเข้าสู่ระบบ ลงทะเบียนเอกสาร แก้ไข เปลี่ยนสถานะ แนบไฟล์ อัปเดตไฟล์
ลบเอกสาร รับทราบเอกสาร จัดการผู้ใช้งาน และการส่งออกชุดกู้ชีพ

ผู้มีสิทธิ์ดูบันทึกกิจกรรม ได้แก่ ผู้ดูแลระบบ หัวหน้างาน หัวหน้าหมวดงาน และผู้จัดการเอกสาร

### 18.3 การตรวจบันทึกกิจกรรม

หัวหน้างานหรือผู้ที่ได้รับมอบหมายสุ่มตรวจบันทึกกิจกรรม**อย่างน้อยทุก 6 เดือน**
เพื่อหาความผิดปกติ เช่น การลบเอกสารที่ไม่มีเหตุผลรองรับ การเข้าใช้งานนอกเวลาผิดปกติ
หรือการเปลี่ยนสถานะเอกสารโดยผู้ไม่เกี่ยวข้อง แล้วบันทึกผลการตรวจไว้

## 19. การตรวจสอบความถูกต้องของระบบ

### 19.1 ก่อนเริ่มใช้งานและหลังการเปลี่ยนแปลง

ต้องตรวจอย่างน้อยหัวข้อต่อไปนี้ และบันทึกผลไว้เป็นหลักฐาน

1. จำนวนเอกสารในทะเบียนตรงกับก่อนเปลี่ยนแปลง
2. เข้าสู่ระบบได้ทุกระดับสิทธิ์ และสิทธิ์ทำงานถูกต้อง
3. เปิดและดาวน์โหลดไฟล์แนบได้
4. ลงทะเบียนเอกสารใหม่และเปลี่ยนสถานะได้
5. รับทราบเอกสารได้และบันทึกลงฐานข้อมูลจริง
6. บันทึกกิจกรรมยังทำงาน
7. การสำรองข้อมูลรอบถัดไปสำเร็จ

### 19.2 การตรวจประจำ

ผู้ดูแลระบบตรวจสุขภาพระบบ**อย่างน้อยเดือนละครั้ง** ครอบคลุมผลการสำรองข้อมูล
ผลการทดสอบกู้คืน พื้นที่จัดเก็บคงเหลือ และข้อผิดพลาดที่พบในบันทึกของระบบ

## 20. การสำรองข้อมูลและความต่อเนื่อง

ดำเนินการตาม **ระเบียบปฏิบัติการสำรองและกู้คืนข้อมูลระบบสารสนเทศ** โดยสรุป

| หัวข้อ | ค่าที่กำหนด |
|---|---|
| ความถี่การสำรอง | ทุก 6 ชั่วโมง |
| RPO | 6 ชั่วโมง |
| RTO | 1 วันทำการ |
| ที่เก็บนอกสถานที่ | บริการจัดเก็บบนคลาวด์ของหน่วยงาน |
| ระยะเก็บสำเนาฐานข้อมูล | รายวัน 30 วัน · รายสัปดาห์ 12 สัปดาห์ · รายเดือน 5 ปี |
| ไฟล์ที่ถูกลบหรือถูกทับ | เก็บแยกในโฟลเดอร์ตามวันที่ |
| การทดสอบกู้คืน | อัตโนมัติทุกเดือน เก็บผลเป็นหลักฐาน 5 ปี |
| การแจ้งเตือน | ส่งอีเมลถึงผู้ดูแลระบบทันทีเมื่อการสำรองล้มเหลว |

## 21. แผนรองรับกรณีระบบใช้งานไม่ได้

### 21.1 ชุดกู้ชีพออฟไลน์

ระบบมีคำสั่งส่งออกชุดกู้ชีพเป็นไฟล์บีบอัด ประกอบด้วยทะเบียนเอกสารทั้งหมด
พร้อมไฟล์จริง เปิดใช้ได้โดยไม่ต้องต่อเครือข่าย

**ผู้รับผิดชอบต้องส่งออกชุดกู้ชีพอย่างน้อยเดือนละครั้ง** เก็บไว้ในสื่อบันทึกที่แยกจาก
เครื่องแม่ข่าย และบันทึกวันที่ส่งออกไว้เป็นหลักฐาน

> ไฟล์แนบที่มีขนาดใหญ่เกินขีดจำกัดจะไม่ถูกรวมในชุดกู้ชีพ ระบบจะระบุไว้ในรายการ
> เอกสารสำคัญที่มีไฟล์ขนาดใหญ่ ให้ดาวน์โหลดแยกเก็บไว้ด้วย

### 21.2 ขั้นตอนเมื่อระบบใช้งานไม่ได้

1. แจ้งผู้ดูแลระบบและหัวหน้างานทันที
2. ใช้ชุดกู้ชีพออฟไลน์ฉบับล่าสุดเป็นเอกสารอ้างอิงระหว่างแก้ไข
3. บันทึกงานที่เกิดขึ้นระหว่างระบบขัดข้องลงกระดาษ พร้อมระบุวันเวลา
4. เมื่อระบบกลับมาใช้ได้ บันทึกย้อนหลังเข้าระบบให้ครบ
5. บันทึกเหตุการณ์ลงทะเบียนความไม่สอดคล้อง ระบุระยะเวลาที่ขัดข้อง สาเหตุ ผลกระทบ
   และแนวทางป้องกันการเกิดซ้ำ

### 21.3 กรณีข้อมูลสูญหาย

ดำเนินการกู้คืนตามระเบียบปฏิบัติการสำรองและกู้คืนข้อมูล และต้องประเมินว่ามีข้อมูล
ในช่วง RPO สูญหายหรือไม่ หากมี ต้องระบุรายการที่หายและบันทึกใหม่ให้ครบ

## 22. การเปลี่ยนแปลงระบบ

การเปลี่ยนแปลงใดที่กระทบวิธีควบคุมเอกสารหรือความถูกต้องของข้อมูล ต้อง

1. แจ้งหัวหน้างานและได้รับความเห็นชอบก่อน
2. สำรองข้อมูลก่อนดำเนินการ
3. ทดสอบตามข้อ 19.1
4. บันทึกไว้ว่าเปลี่ยนอะไร เมื่อใด โดยใคร และผลการทดสอบ
5. แจ้งผู้ใช้งานหากมีผลต่อวิธีใช้งาน

## 23. การฝึกอบรมผู้ใช้งาน

ผู้ใช้งานใหม่ต้องได้รับการชี้แจงก่อนเริ่มใช้ระบบ อย่างน้อยครอบคลุม

- การเข้าสู่ระบบและการตั้งรหัสผ่าน
- การค้นหาและอ่านเอกสาร
- การรับทราบเอกสารและความหมายของลายมือชื่ออิเล็กทรอนิกส์
- **ข้อควรระวังเรื่องการอัปเดตไฟล์ตามข้อ 9.3**
- ข้อห้ามเรื่องข้อมูลส่วนบุคคลตามข้อ 17
- ข้อปฏิบัติเรื่องการพิมพ์เอกสารตามข้อ 11

ระบบมีหน้าคู่มือการใช้งานในตัว ให้ใช้ประกอบการอบรม
ทบทวนความเข้าใจของผู้ใช้งานทุกคน**ปีละครั้ง** บันทึกการอบรมเก็บตามระเบียบการฝึกอบรมบุคลากร

## 24. ข้อบกพร่อง ข้อร้องเรียน และการปรับปรุง

ผู้ใช้งานที่พบข้อบกพร่องของระบบหรือของเอกสาร ให้แจ้งผู้ดูแลระบบหรือหัวหน้าหมวดงาน

| ระดับ | ตัวอย่าง | การดำเนินการ |
|---|---|---|
| เร่งด่วน | ระบบใช้งานไม่ได้ · ข้อมูลสูญหาย · เอกสารผิดที่กระทบความปลอดภัย | ดำเนินการทันที บันทึกความไม่สอดคล้อง |
| ทั่วไป | ใช้งานไม่สะดวก · ข้อมูลแสดงผิด | บันทึกและแก้ไขตามลำดับความสำคัญ |
| ข้อเสนอแนะ | ขอฟังก์ชันเพิ่ม | รวบรวมเสนอในการทบทวนของฝ่ายบริหาร |

ทุกข้อบกพร่องที่กระทบความถูกต้องของเอกสารหรือบันทึก ต้องวิเคราะห์สาเหตุราก
และกำหนดการแก้ไขเพื่อป้องกันการเกิดซ้ำ

## 25. ตัวชี้วัดของกระบวนการ

เสนอให้ติดตามและรายงานในการทบทวนของฝ่ายบริหาร

| ตัวชี้วัด | เป้าหมายที่เสนอ | ความถี่ |
|---|---|---|
| ร้อยละเอกสารที่ทบทวนตามกำหนด | ≥ 95% | ทุก 3 เดือน |
| ร้อยละการรับทราบเอกสารฉบับปัจจุบันครบภายใน 30 วัน | ≥ 90% | ทุก 3 เดือน |
| จำนวนครั้งที่การสำรองข้อมูลล้มเหลว | 0 | ทุกเดือน |
| ผลการทดสอบกู้คืนข้อมูล | ผ่านทุกครั้ง | ทุกเดือน |
| จำนวนเหตุการณ์ระบบใช้งานไม่ได้เกิน RTO | 0 | ทุกปี |
| ร้อยละผู้ใช้งานที่บันทึกอีเมลครบ | 100% | ทุก 6 เดือน |

**เป้าหมายทั้งหมดต้องได้รับความเห็นชอบจากหัวหน้างานก่อนบังคับใช้**

## 26. การตรวจติดตามภายในและการทบทวนของฝ่ายบริหาร

กระบวนการนี้ต้องถูกตรวจติดตามภายใน**อย่างน้อยปีละครั้ง** ครอบคลุม

- ความครบถ้วนและถูกต้องของทะเบียนเอกสาร
- หลักฐานการทบทวนและอนุมัติเอกสาร
- หลักฐานการรับทราบ
- บันทึกกิจกรรมและการตรวจบันทึก
- ผลการสำรองและทดสอบกู้คืน
- การทบทวนสิทธิ์ผู้ใช้งาน

ผลการตรวจติดตาม ผลตัวชี้วัด และข้อบกพร่องที่พบ ต้องนำเข้าการทบทวนของฝ่ายบริหาร

## 27. เอกสารด้านความปลอดภัยตาม ISO 15190

> **หมายเหตุสำคัญ** มาตรฐานความปลอดภัยห้องปฏิบัติการทางการแพทย์ฉบับปัจจุบันคือ
> **ISO 15190:2020** ไม่มีฉบับปี 2022 ระเบียบนี้จึงอ้างอิงฉบับ 2020

ระบบนี้ไม่ใช่ระบบบริหารความปลอดภัย แต่เป็น**เครื่องมือควบคุมเอกสารและบันทึกด้านความปลอดภัย**

### 27.1 สิ่งที่ระบบรองรับ

| สิ่งที่ระบบทำได้ | ประโยชน์ต่อข้อกำหนดความปลอดภัย |
|---|---|
| ควบคุมคู่มือความปลอดภัยและระเบียบปฏิบัติด้านความปลอดภัยให้เป็นฉบับล่าสุด | เอกสารความปลอดภัยที่ใช้งานเป็นฉบับปัจจุบันเสมอ |
| เก็บหลักฐานว่าผู้ปฏิบัติงานรับทราบเอกสารความปลอดภัยฉบับใด | พิสูจน์การสื่อสารข้อกำหนดความปลอดภัยถึงผู้ปฏิบัติ |
| เก็บแบบฟอร์มและบันทึกด้านความปลอดภัยตามระยะจัดเก็บ | บันทึกความปลอดภัยเรียกใช้ได้เมื่อต้องการ |
| ตรวจสอบย้อนกลับได้ว่าใครแก้เอกสารความปลอดภัยเมื่อใด | ความรับผิดชอบชัดเจน |
| ชุดกู้ชีพออฟไลน์ | เข้าถึงขั้นตอนความปลอดภัยได้แม้ระบบล่ม |

### 27.2 สิ่งที่ต้องดำเนินการนอกระบบ

การประเมินความเสี่ยงด้านความปลอดภัย · การรายงานและสอบสวนอุบัติการณ์ ·
การเฝ้าระวังสุขภาพผู้ปฏิบัติงาน · การจัดการของเสีย · การฝึกซ้อมแผนฉุกเฉิน ·
การตรวจสอบอุปกรณ์ป้องกันส่วนบุคคล

เนื่องจากบันทึกการเฝ้าระวังสุขภาพเป็นข้อมูลอ่อนไหว และระบบให้สิทธิ์ตามบทบาท
ไม่ใช่รายเอกสาร **ห้ามนำบันทึกสุขภาพรายบุคคลเข้าระบบนี้** ตามข้อ 17

## 28. ข้อจำกัดของระบบที่ต้องควบคุมด้วยวิธีอื่น

รวบรวมไว้ที่เดียวเพื่อให้ผู้ตรวจประเมินเห็นว่าห้องปฏิบัติการรู้และควบคุมแล้ว

| ข้อจำกัด | มาตรการชดเชย | ข้อ |
|---|---|---|
| อัปเดตไฟล์แล้วไฟล์เดิมถูกลบจากระบบ | ดาวน์โหลดเก็บก่อนอัปเดต · มีสำเนาในระบบสำรอง | 9.3 |
| ไม่มีการแจ้งเตือนเมื่อถึงกำหนดทบทวน | ตรวจทะเบียนด้วยตนเองทุก 3 เดือน | 14 |
| สิทธิ์เป็นแบบตามบทบาท ไม่ใช่รายเอกสาร | ห้ามนำข้อมูลที่ต้องจำกัดการเข้าถึงเข้าระบบ | 17 |
| ลิงก์ภายนอกไม่ใช่เอกสารควบคุม | ดาวน์โหลดมาแนบเป็นไฟล์เมื่อจำเป็นต่อการปฏิบัติงาน | 9.4 |
| เอกสารที่พิมพ์ออกมาไม่ถูกควบคุมโดยระบบ | ประทับสถานะสำเนาและขึ้นทะเบียนจุดแจกจ่าย | 11 |
| ระบบทะเบียนบุคลากรยังไม่มีการทดสอบกู้คืนอัตโนมัติ | ทดสอบด้วยมือปีละครั้ง | ระเบียบสำรองข้อมูล |
